`безопасность`. Статус: готовый черновик, не опубликован. Это текст,

## Статья

Fragment Donor — независимый сервис и набор SDK, не официальный продукт Telegram,
Fragment или TON. Здесь нет демонстрации реальной покупки, обещаний безопасности
кошелька или гарантированной индексации документации.

У прямого API `https://fragment.donor.uz` нет сервисной авторизации: не нужны
регистрация, `Authorization`, `X-Api-Key` или отдельный ключ сервиса. Но покупка
использует ваш `Mnemonic` кошелька и `Cookie` сессии Fragment. Необязательный
`Api-Key` — ключ провайдера TonConsole, а не вход в этот сервис.

Начните с одного запроса без секретов:

```python
from fragment_donor_sdk import FragmentDonorClient

client = FragmentDonorClient(timeout=30)
user = client.get_user_info("durov")
print(user.username, user.is_premium)
```

Версия Python SDK — 0.1.0, Python 3.10+. Пока публикация в PyPI не подтверждена,
используйте чистый исходный репозиторий и `python -m pip install ./python` из его
корня. После реального релиза команда будет
`python -m pip install fragment-donor-sdk==0.1.0`.

Четыре операции используют один контракт: GET `/get-user-info/` с `username`,
POST `/buy-stars/` с формой `username`/`amount`, POST `/buy-premium/` с
`username`/`duration`, GET `/wallet-balance/` с Mnemonic. Backend также принимает
POST для баланса. Покупки отправляются как form-urlencoded, а не JSON.

Stars: целое число 50–1 000 000. Premium: 3, 6 или 12 месяцев. Оплата:
`usdt_ton` по умолчанию либо `ton`. Версия кошелька: `auto`, `v5r1`, `v4r2`,
`v3r2`. Значения баланса сохраняются как десятичные строки; не переводите их в
`float`/JavaScript `Number`, если важно сохранить все цифры.

Обычный общий лимит — 30 запросов в минуту на IP для всех четырёх операций.
429 содержит `FLOOD_WAIT`, заголовок `Retry-After` и JSON-подсказки ожидания.
Клиенты учитывают секунды, HTTP-date и выбирают максимальную валидную подсказку.
Автоматическое ожидание выключено; только чтение можно явно настроить на максимум
два повтора с ожиданием до 60 секунд. Если сервер требует больше, клиент вернёт
ошибку, а не сократит обязательное ожидание.

Покупки никогда не повторяются автоматически — даже при 429, 503, таймауте или
5xx. Первый POST мог списать деньги, хотя ответ потерялся. Нет гарантии
idempotency-key или endpoint статуса покупки. Сохраните состояние «результат
неизвестен», проверьте историю кошелька/получателя и только потом принимайте
решение о новой намеренной покупке. Ответ HTTP 400 с `unconfirmed:true` и
`tx_hash` тоже означает неизвестный результат платежа, а не обычный отказ
валидации. Сохраните безопасную ссылку на транзакцию для сверки; код 400 не
доказывает, что деньги не были потрачены.

Особенно важно: изученный backend сохраняет переданные учётные данные в базе.
Редактирование секретов в SDK-логах не означает нулевое хранение на сервере или
non-custodial модель. Держите секреты на доверенном сервере, используйте отдельный
минимально пополненный кошелёк и осознанно оцените доступ оператора. Не помещайте
mnemonic в frontend, localStorage, Git, скриншоты или переменные публичного Postman.
